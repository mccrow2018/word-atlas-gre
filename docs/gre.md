# GRE PDF 词库

两份 PDF 分别导入，不合并单词、分组或学习进度。首页和「我的」均可切换；原有雅思图鉴保留。

| --- | ---: | --- |
| 真经 GRE 等价词汇总 | 905 | 5 天：180 / 182 / 181 / 177 / 185 |
| GRE 镇考机经词 7.0（乱序版） | 1450 | 7 天：210 / 210 / 210 / 210 / 210 / 210 / 190 |

## 等价词的固定计划

在首页点击「从今天开始 5 天计划」记录本设备的开始日期。每天的范围和顺序与 PDF 一致，等价词保留在同一词条内，可分别点击发音。每轮学习最多 20 个新词，可暂停、刷新、切换词库后继续。

下一天需要同时满足：前一天全部词条已答过题，并到达对应的日历日期。错题会进入复习；完成任务表示学过，不代表全部掌握。漏学不会跳到未来任务。普通的每日新词额度和难度设置不改变此计划，额外学 5 个的入口在该词库中关闭。未来词表可预览，但不会提前加入学习任务。完成五天后继续使用 FSRS 复习。

机经词库参照等价词的 5 天任务重排，每天安排 200 个新词，每轮最多 20 个，可连续完成 10 轮。第 1～5 学习日固定优先放入当天所有相同主词条，余位按原资料等价关系、共同等价词、相同中文释义的优先级做全局匹配。相同主词条不会被提前拿去填充其他日期，组内相对词序跟随等价词。第 6～7 天各 200 条，第 8 天剩余 50 条。

| 学习日 | 机经新词 | 与当天等价词相同的主词条 | 有关联的补充词 |
| --- | ---: | ---: | ---: |
| 1 | 200 | 167 | 33 |
| 2 | 200 | 164 | 36 |
| 3 | 200 | 168 | 32 |
| 4 | 200 | 166 | 34 |
| 5 | 200 | 166 | 34 |

等价词的每日任务和词序完全不变。关联依据保存在每个机经词的学习元数据中；关联不表示可以无条件互换。机经原书 7 个 DAY（每组通常 210 条）仍保留用于查阅筛选，新学习日另外筛选。两份词库应从同一天开始、每天完成对应任务以获得上述重合；已有学习记录不清空，已学词会跳过，未学词沿新顺序补足每日 200 个，因此中途改序后的实际单日词表可能跨推荐学习日。进行中的旧学习轮次可继续，下一轮使用新顺序。

完整 1,450 条词条、释义、例句、原分组和稳定 ID 均未修改，只新增 `learning` 元数据；等价词文件的 SHA-256 在报告和测试中锁定。普通雅思词库的每日新词设置不影响这两份 GRE 词库。重排报告见 `data/gre-alignment-report.json`。

## 数据和发音

- 浏览器使用 `public/gre/gre-equivalent.json`、`public/gre/gre-core.json`，词条保留源 PDF 页码、行号和 DAY。
- 释义、原例句、等价关系来自用户提供的 PDF；没有补写不存在的例句或中文译文。数据署名为原 PDF 的张巍 GRE／真经 GRE，原作者权利保留，未将这些数据重新声明为项目原有的 CC BY 4.0 内容。
- 发音和插画仅复用雅思图鉴中拼写完全相同的单词素材；缺失的单词及等价词使用浏览器设备语音。英美口音可切换，声音质量和可用性取决于设备的英语语音支持。
- 原 PDF 的例句与雅思例句不同，不复用雅思例句音频。
- PDF 表格中有一条 `reinvent` 例句被截断，暂不导入；`boundary` 的音标印为 `qq`，留空以使用可用音标或朗读。恢复了 `at a premium`、`at odds with` 的短语空格。详细记录见 `data/gre-import-report.json`。

## 重新导入

将两份源文件命名为 `ro6t.pdf` 和 `nm7j.pdf` 放到 `tmp/pdfs/`，安装 `pdfplumber` 后运行：

```sh
python scripts/gre/import_pdfs.py --pdf-dir tmp/pdfs
python scripts/gre/test_align_core.py
npm test
npm run build
```

界面回归验证：先运行 `npm run dev`，另一个终端执行 `node scripts/check-gre.mjs`（需要先 `npx playwright install chromium`）。覆盖独立进度、刷新续学、每日解锁、英美发音路由及手机布局；截图保存至 `tmp/`。

脚本按表格边界提取单元格，排除大字号斜向水印，保留原顺序并校验 5／7 天分组。`tmp/pdfs/*-tables.json` 是加速重跑的中间缓存，更新源 PDF 时需要删除对应缓存。

导入后自动执行机经重排。单独重排现有 JSON（不读取或修改 PDF，也不写入等价词文件）：`python scripts/gre/align_core.py`。分配使用矩形匈牙利算法，固定同日主词条后，在前五天的剩余容量之间最大化有依据的关联；结果可重复生成。
